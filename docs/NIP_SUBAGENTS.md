# UN-v2.0: NIPs as Subagents (The Governance Mesh) 🜏

## Overview

In the UN-v2.0 (ONU 2.0) architecture, every **NIP (Nostr Implementation Possibility)** is treated as a specialized **Subagent** or **Subnet** within the larger governance mesh. This follows the **Mesh-LLM** (Bittensor-style) pattern, where each NIP provides a distinct "skill" or "service" to the platform.

## Mapping NIPs to Subagents

| NIP | Subagent Role | Governance Skill |
| :--- | :--- | :--- |
| **NIP-01** | **Identity Subagent** | Basic protocol infrastructure and event relaying. |
| **NIP-04** | **Confidentiality Subagent** | Encrypted direct messaging for private governance discussions. |
| **NIP-34** | **Git Subagent** | Sovereign version control for jurisdictional projects. |
| **NIP-46** | **Remote Signer Subagent** | Delegated signing for jurisdictional transactions. |
| **NIP-89** | **Discovery Subagent** | Identifying and indexing new governance subnets. |
| **NIP-94** | **File Storage Subagent** | Distributing jurisdictional binaries and large datasets. |

## The Mesh-LLM Pattern (Bittensor Integration)

The governance platform operates like a **Mesh-LLM**:
- **Validators (Main Dashboard)**: The ONU 2.0 dashboard acts as a validator, scoring the contributions of various NIP-subagents.
- **Miners (Subnets)**: Individual NIP-subagents "mine" the $\tau$-field for coherent governance solutions.
- **Incentive Layer**: Coherence ($R$) is the primary metric for resource allocation within the mesh.
